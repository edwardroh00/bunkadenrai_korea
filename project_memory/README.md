### 구현 순서

1. **관람 공연 → 곡 기록:** 공연 목록·세트리스트·관람 체크를 연결해 들어본 곡, 미청취곡, 가장 많이 들은 곡을 계산한다.
2. **구매 기록 → 보유 컬렉션·사이즈:** 기존 굿즈 도감과 구매 기록을 활용하고, 실제 보유 상태와 사이즈·착용감 기록을 보완한다.
3. **개인 홈:** 두 기록을 모아 자신의 덕질 경험을 돌아볼 수 있는 통계·컬렉션 화면을 만든다.
4. **여러 팬에게 확장:** 사용자별 저장·로그인·기기 간 동기화를 구체화한다. 초기부터 공통 데이터와 개인 기록을 분리하고 백업·이관 경로를 유지한다.

현재는 정적 HTML/CSS/JavaScript 사이트, 공식 출처가 연결된 굿즈 도감, 옵션·수량·실제 단가·구매/수령일·상태를 저장하는 구매 기록과 JSON 백업, 71곡의 한글·일본어·영문 곡명 매칭을 갖추고 있다. 개인 기록은 브라우저 로컬 저장 방식이다.

- **보유 굿즈:** 현재 실제로 가진 수량. 위시리스트·구매 예정·주문 완료와 따로 계산한다. 선물이나 과거 구매도 등록하고 양도·분실 등 소유 변화도 보존한다.

- **들어본 곡:** 관람한 공연에서 실제로 들은 곡. 일반 음원 청취는 기본 통계에 합치지 않는다. 현장·온라인 및 전체·부분 관람을 구분한다.

- **미청취곡·달성률:** 기준일과 대상 곡 범위를 표시한다. 원곡, 커버·참여곡, 미발매 발표곡, 라이브 버전을 구분한다. 세트리스트가 불완전하거나 관람 구간이 미확인이면 미청취를 단정하지 않는다.
- **곡 연결:** 한글·일본어·영문/로마자 이름을 하나의 곡 ID로 연결한다. 메들리는 구성곡을 기록하고 편곡과 원곡의 관계를 보존한다.
- **개인화:** 공통 곡·공연·상품 목록과 개인 보유·사이즈·관람·메모 기록을 분리한다. 여러 팬으로 확장해도 개인 기록을 사용자 간에 섞지 않는다.
